# Collective Belfry

Belfry (the Collective Bunker) runs access and identity for Open Source Village: EUDI-wallet pass certificates (SD-JWT VC via OpenID4VCI/VP), Nostr-based community apps behind a Keycast signer (Divine's fork), and Odoo as the registry of who holds which pass.

## Current status

Plan verified against the real software on 2026-10-22 (spike notes in `docs/research/`); decisions recorded in @docs/NEXT_STEPS.md §2. Build slice 1 (Phase 1 onboarding: Compose stack, Odoo module `belfry_pass`, onboarding service) is built and green locally; its contract is @docs/slice-1-onboarding.md. Phase 2 has started: the community relay (rnostr, `infra/relay/`) with a NIP-42 whitelist derived from active passes and kind-0 profiles published at activation, the Keycast fork (patch series in `infra/keycast/build/patches/`) whose login goes through Authentik, and the participants' Authentik login itself, passwordless: a one-time sign-in link mailed by Odoo at activation, then e-mail magic links or the pass on the login page (2026-10-23, §3j). Phase 3 is built locally: walt.id Issuer2 issues the village-pass SD-JWT VC from the claim page, the onboarding service serves the status list, type metadata, a door check and the OpenID4VP-to-OIDC bridge over walt.id Verifier2 that signs participants in to Authentik with the pass (`infra/issuer/README.md`, 2026-10-23). The whole happy path runs locally with a scripted wallet; a first hardening pass (Odoo mail over SMTP, least-privilege service user, master password, issuer certificate pinning, signed verifier requests) is in (§3f), the Keycast fork carries Belfry branding and key export for OIDC-only accounts (patches 0004–0005, image built and verified) and a gated Blossom file server is in the stack (§3h). A public test deployment runs on `belfry.tofauti.net` (`infra/DEPLOY.md`, §3i) with the full smoke test green over TLS; another Claude session shares that VM, coordinate before touching it. Participant-facing surfaces are branded "Open Source Village, run by Belfry" (dark theme, mobile first, shared `brand/` folder served at `/brand` by the onboarding service; §3l, 2026-10-23); stewards use Belfry's own steward pages, not the Odoo UI (§3k). The community chat and calendar sign in with "Sign in with Open Source Village" through Keycast, silently when the participant is already signed in (Keycast patch 0008, §3q); logging out of an app ends the sign-in everywhere (patch 0010, §3r). Every pass brings village tokens (Cashu, no monetary value, 50 per pass day) from Belfry's mint, kept in the wallet at wallet.<domain>, which derives its keys from the participant's Nostr key and sends nutzaps; participants can move to a key of their own (Keycast patch 0012, §3s). Participant keys derive from a custody seed kept under the stewards' YubiKeys, so they can be recovered from the seed and Odoo (Keycast patch 0014, §3t); nightly backups are encrypted to a backup key under the same YubiKeys and go off the VM, with a restore drill (`infra/scripts/backup.sh`, §3t). DIDs are dropped (2026-10-24); the extras are polls, a directory and a marketplace paid in tokens (`services/village`, §3u) and photos. Next work is in @docs/NEXT_STEPS.md §4. Run `make up && make bootstrap && make up-app && make smoke` to see it work.

## Key rules from the plan

- Identity and membership stay separate: the Nostr key belongs to the member (managed, recoverable or self-custodied); membership (Odoo record + signed certificate) belongs to Belfry. Revoking membership never touches the key.
- Odoo is the single source of truth for passes; the relay whitelist and certificates are derived from it.
- Payment runs through Odoo's own providers (Stripe, Mollie) and Odoo payment links. Belfry's onboarding glue is idempotent, keyed on the Odoo invoice and the provider's payment reference; Belfry's own Stripe endpoint (disputes only) is keyed on the Stripe event id, Mollie's refunds and chargebacks come through Odoo (`belfry_pass`, keyed on the refund and chargeback ids). Access only after the invoice is paid.
- One credential type (`vct` `village-pass/v1`) for all tiers; tier and dates are claims. Door checks disclose only tier, validity and status.
- No DIDs: did:webvh and the id.<domain> endpoint were dropped on 2026-10-24 (Phase 4); the issuer key is published through jwt-vc-issuer metadata and x5c.
- Event release = Phases 0–3 (governance, onboarding/registry, Collective Bunker, EUDI pass certificates). Self-custody is built already; DIDs are dropped.
